Pages for everyone

Check a page works for everyone: pictures described with alt, headings as the page's outline, labels joined to their boxes, links that say where they go, readable colours; then test it with a classmate.

About one in five people has a disability. A page built with the right tags works for screen readers, keyboards and phones as well as for you.

Not everyone uses a page the way you do. Some people hear it through a screen reader, which reads the tags aloud; some use only a keyboard; some see it small or with poor contrast. A page works for all of them when its tags say what each part is. The checklist:

  1. Pictures have alt text that says what they show (or alt="" if they are only decoration).
  2. Headings are the page's outline: one <h1>, then <h2>, then <h3>, never chosen for their size.
  3. Boxes have a <label> joined by for and id.
  4. Links say where they go: not "click here".
  5. Colours are easy to read: dark text on a light background, or the other way round.
  6. The keyboard reaches everything: press Tab through the page.

The same list works for a hand-built page, a Bootstrap page or a Vue app: they all end up as tags in the browser.

      For teachers

      Students predict what a screen reader says for a picture with no alt and a "click here" link, move through an accessible page with the keyboard, match problems to fixes, find headings chosen for size, fix pictures and labels, then check their own page and test it with a classmate. About 55 minutes.

      Open the teacher guide: answers, solutions, slides and a worksheet.

      Students will be able to

      • I can check a page for alt text, headings, labels, link text, contrast and keyboard use.
      • I can fix a page so a screen reader and a keyboard can use it.
      • I can test my page with a real person and fix what they find.

      Before class

      The lesson works on any page, from any route through the Web pathway: Bootstrap and Vue pages end up as ordinary tags in the browser, so the same checks apply. Nothing new is taught about HTML: alt, headings, labels and links all appear in HTML & CSS; this lesson is about why they matter and checking for them.

      The checklist follows the most common failures in automated checks of real home pages (missing alt text, missing form labels, low contrast and empty or vague links top the WebAIM Million survey every year). Contrast is hard to judge by eye: in Chrome or Edge, right-click the page, Inspect, and the colour picker shows a contrast ratio (4.5 or more for normal text). Screen readers: Narrator (Windows, Ctrl + Windows + Enter) or VoiceOver (Mac, Command + F5) let students hear their page; turn them off the same way.

      The classmate test is the important part: a five-minute test with one person finds more problems than a checklist. Students give one task and watch without helping.

      Running the lesson

      1. Predict: if you can, play a screen reader reading a page with no alt (Narrator or VoiceOver).
      2. Run: everyone presses Tab through the preview. Ask what the outline around each part is for.
      3. Investigate: for the bug, ask how a screen reader user moves around a page (by headings).
      4. Modify: ask students to say each alt text aloud: does it say what the picture shows?
      5. Make: pair students. The tester only tries; the maker only watches and notes, then fixes.

      The hard part (on purpose)

      Students think a page that looks right is right. Ask "how would someone who can't see it, or can't use a mouse, do this?" and let them try with only Tab and Enter.

      When students get stuck

      • Clicking the label does not put the cursor in the box. Ask: Do for and id match exactly, capitals included? Fix: Use the same word in both: for="name" and id="name".
      • Tab skips a button or link. Ask: Is it a real button or a tag (a, input) that can take focus, or a div made to look like one? Fix: Use button or a; a clickable div is invisible to the keyboard.
      • Long alt text that repeats the caption. Ask: What would you say to a friend on the phone about this picture? Fix: A short description; alt="" if the picture is only decoration.

      Stretch and support

      Stretch: Run Chrome's Lighthouse accessibility check (Inspect, Lighthouse) on a real website and on your page. Listen to your page with Narrator or VoiceOver.

      Support: Give students the six points as a printed tick sheet for their own page.

      What each step is for

      • Predict: Students assume a screen reader can see the picture; hearing that it reads the file name makes alt text matter.
      • Investigate: Most fixes are the right tag or attribute, not a new look: alt, heading levels, labels and link text.
      • Modify: Fixing a page for everyone is small, exact changes to tags and attributes.
      • check your own page: Goals only: apply the checklist to their own page, then test it with a real person.
